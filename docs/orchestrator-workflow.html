Orchestrator workflow

The orchestrator skill drives a feature from a user story to a merged PR through 10 phases. Each phase dispatches helper subagents or invokes companion skills as needed. The diagram below maps phase → components → artifacts.

Phase flow

Phases run top to bottom along the left spine; inside each phase the work reads left to right. Solid arrows are the main path; dotted arrows are guidance, bootstrap and the two loop-backs (next ready slice, and FIXES_NEEDED from Phase 9 into Phase 8).

Phase → component matrix

Which subagents each phase dispatches, which skills it invokes, and what it leaves behind.

PhaseSubagents dispatchedSkills invokedOutput
1 Discovery - - Captured ACs, ticket metadata, and the tier (full-stack / one-layer / refactor) that sizes every later phase
2 Codebase Exploration 2–3× code-explorer (parallel); 1 for a one-layer feature; none for the refactor tier, where the orchestrator's own grep census is the exploration codebase-context-builder (if missing) Reference impl, patterns, key files
3 Clarifying Questions - - Resolved decisions
4 Architecture Design & Documents 1× code-architect (designs and writes the 6 docs directly - no orchestrator transcription, closing the old ~20-min gap) git-worktrees (isolate, first), vertical-slicing (slice shape + frozen per-slice contracts + the machine-readable dependency DAG) 6 plan files in docs/new-feature/{id}/; slice list + frozen contracts + a ## Dependency graph block in 04-task-plan.md (authoritative edge table + waves + critical path)
5 Finalize Documents - - Verified/consistent docs + README index
6 Quality Review 2× plan-reviewer (parallel); 1 for a one-layer feature; none for the refactor tier - Review findings, doc fixes
7 Summary - - Hand-off briefing
8 Slice-by-slice Impl

Step 1 (implement only, no per-slice integration): the ready-frontier and critical path are computed from 04-task-plan.md's ## Dependency graph block (critical-path-first when worktree slots are scarce); parallel-safe slices run concurrently in worktrees; within each, impl-backend and impl-frontend in parallel against the frozen contract - BE implements and conformance-tests it, FE stays on a mock.

Step 2 (once, whole story): one impl-frontend whole-story integration → impl-simplify (isolated context, wraps the built-in simplify skill; runs first so reviewers read the diff that ships) → code-reviewer and security-reviewer in parallel → smoke → regression (one run that is also the coverage gate) → context-updater (review loops back on FIXES_NEEDED).

Kind: sweep slices gate on the build only and run concurrently; the refactor tier (set in Phase 1) drops explorers, plan review, the security reviewer and the walker.
